# 용어 정리

## secure context

브라우저가 안전하다고 판단하는 환경입니다. HTTPS로 접속한 페이지, localhost, 또는 file:// 프로토콜로 열린 파일이 여기에 해당합니다.
MediaRecorder나 getUserMedia() 같은 민감한 API는 보안을 위해 Secure Context에서만 사용할 수 있습니다.
HTTP로 접속한 일반 웹사이트에서는 이러한 API를 사용할 수 없어, 개발 시에는 HTTPS나 localhost를 사용해야 합니다.

## MediaRecorder와 MediaStream의 관계

MediaRecorder는 MediaStream을 생성자로 받아서 그 스트림의 데이터를 읽어서 Blob으로 기록하는 도구입니다.
MediaRecorder.stop()을 호출하면 기록은 중지되지만, MediaStream은 계속 데이터를 흘려보냅니다. 즉, MediaRecorder는 MediaStream의 "독자" 역할을 하며, 스트림 자체를 제어하지는 않습니다.
MediaStream을 완전히 중지하려면 stream.getTracks().forEach(track => track.stop())을 별도로 호출해야 하며, 이는 수도꼭지(MediaStream)에서 물을 받는 컵(MediaRecorder)을 치워도 수도꼭지는 계속 물을 흘리는 것과 같은 원리입니다.

## MediaRecorderOptions

MediaRecorder를 생성할 때 전달하는 설정 객체입니다.
mimeType(예: "audio/webm"), audioBitsPerSecond(오디오 비트레이트), videoBitsPerSecond(비디오 비트레이트) 등을 지정할 수 있습니다.
이 옵션을 통해 녹화할 파일 형식과 품질을 미리 결정할 수 있어, 용도에 맞는 최적의 설정을 선택할 수 있습니다.

## inactive

MediaRecorder의 초기 상태이자 녹화가 완전히 끝난 상태입니다.
녹화가 시작되기 전이나 stop() 메서드를 호출한 후에 이 상태가 됩니다.
이 상태에서는 녹화 관련 작업을 할 수 없으며, start()를 호출해야 recording 상태로 전환됩니다.

## recording

MediaRecorder가 현재 오디오나 비디오를 녹화하고 있는 활성 상태입니다.
start() 메서드를 호출하면 이 상태가 되며, 데이터가 실시간으로 수집됩니다.
이 상태에서는 pause()로 일시 정지하거나 stop()으로 완전히 중지할 수 있습니다.

## paused

MediaRecorder가 일시 정지된 상태로, 녹화는 중단되었지만 아직 완전히 끝나지 않은 상태입니다.
pause() 메서드를 호출하면 recording 상태에서 이 상태로 전환되며, resume()으로 다시 녹화를 재개할 수 있습니다.
일시 정지 중에도 이전에 녹화한 데이터는 유지되며, resume() 후에는 그 지점부터 이어서 녹화가 진행됩니다.

## ondataavailable

MediaRecorder가 데이터 청크를 생성할 때 발생하는 이벤트입니다.
timeslice를 지정했을 때 주기적으로 발생하거나, stop() 호출 시 마지막 데이터와 함께 발생합니다.
이 이벤트의 data 속성에 Blob 객체가 담겨 있어, 실시간으로 오디오 데이터를 수집하거나 전송할 수 있습니다.

## Blob 변환 원리

MediaStream은 마이크나 카메라에서 계속 데이터를 흘려보내는 흐름입니다. MediaRecorder는 이 흐르는 데이터 중 일정 시간(timeslice) 동안 흐른 부분만 읽어서 Blob으로 변환합니다.
timeslice를 지정하면(예: start(100)) 100ms마다 그동안 흐른 데이터를 하나의 Blob 청크로 만들어서 ondataavailable 이벤트로 전달합니다. 스트림은 계속 흐르지만, 기록된 부분만 Blob으로 저장되는 것입니다.
이것은 마치 흐르는 강물에서 일정 시간마다 물을 떠서 병에 담는 것과 같습니다. 강물은 계속 흐르지만, 떠서 담은 물만 병에 저장되는 원리입니다.

## immutable data object

한 번 생성되면 내용을 변경할 수 없는 불변 데이터 객체입니다.
Blob과 ArrayBuffer가 대표적인 예로, 생성 후에는 읽기만 가능하고 수정은 불가능합니다.
데이터를 변경하려면 새로운 객체를 생성해야 하며, 이는 데이터의 무결성을 보장하고 예상치 못한 변경을 방지합니다.

## BlobPart

Blob을 생성할 때 전달할 수 있는 데이터 타입들의 유니온 타입입니다.
문자열, ArrayBuffer, TypedArray(Uint8Array 등), 다른 Blob 등이 BlobPart에 해당합니다.
Blob 생성자는 BlobPart 배열을 받아서 하나의 Blob으로 합치므로, 다양한 형태의 데이터를 한 번에 묶을 수 있습니다.

## BlobPropertyBag

Blob을 생성할 때 전달하는 옵션 객체의 타입입니다.
type 속성으로 MIME 타입(예: "audio/webm", "text/plain")을 지정할 수 있습니다.
이 옵션을 통해 생성되는 Blob의 종류를 명시하여, 나중에 파일로 다룰 때 올바른 형식으로 처리할 수 있습니다.

## size

Blob이나 ArrayBuffer의 크기를 바이트 단위로 나타내는 속성입니다.
Blob.size는 Blob에 포함된 데이터의 총 바이트 수를 반환합니다.
이 값을 통해 데이터의 크기를 확인하고, 메모리 사용량을 추적하거나 전송 전 크기 제한을 체크할 수 있습니다.

## type

Blob이 가지고 있는 MIME 타입 정보를 나타내는 문자열 속성입니다.
예를 들어 "audio/webm", "text/plain", "application/octet-stream" 등의 값을 가질 수 있습니다.
이 타입 정보는 브라우저가 데이터를 어떻게 처리할지 결정하는 데 사용되며, 파일 다운로드나 미디어 재생 시 중요합니다.

## 메모리에 직접 접근

ArrayBuffer는 메모리의 특정 영역을 직접 참조하는 원시 바이너리 데이터입니다.
일반 JavaScript 객체와 달리 가비지 컬렉션의 오버헤드가 적어 성능이 중요할 때 유리합니다.
하지만 직접 접근은 불가능하고, TypedArray나 DataView를 통해야 데이터를 읽거나 쓸 수 있습니다.

## arrayBuffer()

Blob을 ArrayBuffer로 비동기적으로 변환하는 메서드입니다.
Promise를 반환하므로 await나 .then()을 사용해서 변환된 ArrayBuffer를 받아야 합니다.
WebSocket으로 전송하거나 바이트 단위로 데이터를 조작해야 할 때 이 메서드를 사용합니다.

## byteLength

ArrayBuffer나 TypedArray가 차지하는 메모리의 바이트 크기를 나타내는 읽기 전용 속성입니다.
ArrayBuffer.byteLength는 버퍼의 고정된 크기를 반환하며, 생성 시 지정한 값과 동일합니다.
이 값을 통해 메모리 사용량을 확인하고, 데이터 크기 제한을 체크하거나 버퍼 할당 계획을 세울 수 있습니다.

## Uint8Array

8비트(1바이트) 부호 없는 정수 배열로, 0부터 255까지의 값을 저장할 수 있습니다.
ArrayBuffer를 읽고 쓸 때 가장 기본적으로 사용되는 TypedArray입니다.
바이너리 데이터를 다룰 때 가장 흔히 사용되며, 각 요소가 정확히 1바이트를 차지해 메모리 효율적입니다.

## Int16Array

16비트(2바이트) 부호 있는 정수 배열로, -32,768부터 32,767까지의 값을 저장할 수 있습니다.
오디오 데이터에서 16비트 PCM 샘플을 다룰 때 주로 사용됩니다.
각 요소가 2바이트를 차지하므로, 같은 크기의 ArrayBuffer에서 Uint8Array보다 절반의 요소만 저장할 수 있습니다.

## Float32Array

32비트(4바이트) 부동소수점 배열로, 소수점이 있는 실수 값을 저장할 수 있습니다.
오디오 처리에서 샘플 값을 -1.0부터 1.0 사이의 실수로 다룰 때 주로 사용됩니다.
웹 오디오 API(AudioContext)에서 오디오 데이터를 처리할 때 이 타입을 자주 사용합니다.

## 풀링

메모리나 객체를 미리 할당해 두고 재사용하는 최적화 기법입니다.
매번 새로운 ArrayBuffer를 생성하는 대신, 사용이 끝난 버퍼를 풀에 보관했다가 다시 사용합니다.
이를 통해 가비지 컬렉션의 부담을 줄이고 성능을 향상시킬 수 있으며, 특히 실시간 오디오 처리에서 유용합니다.
