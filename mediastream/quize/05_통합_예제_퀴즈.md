1. getUserMedia → MediaRecorder → Blob → ArrayBuffer → WebSocket
2. MediaRecorder → getUserMedia → Blob → WebSocket → ArrayBuffer

### Q8. 다음 요구사항을 만족하는 함수를 작성하세요.

- 함수명: `setupAudioPipeline`
- 반환값: `Promise<void>`
- 기능:
  1. getUserMedia로 오디오 스트림 가져오기
  2. MediaRecorder 생성 (MIME 타입: "audio/webm;codecs=opus")
  3. ondataavailable 이벤트 핸들러 설정 (콘솔에 크기만 출력)
  4. 100ms 간격으로 녹화 시작

**정답**:

```typescript
async function setupAudioPipeline(): Promise<void> {
  // 1. 오디오 스트림 가져오기
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });

  // 2. MediaRecorder 생성
  const mediaRecorder = new MediaRecorder(stream, {
    mimeType: "audio/webm;codecs=opus",
  });

  // 3. ondataavailable 이벤트 핸들러 설정
  mediaRecorder.ondataavailable = (event: BlobEvent) => {
    if (event.data && event.data.size > 0) {
      console.log("청크 크기:", event.data.size, "bytes");
    }
  };

  // 4. 100ms 간격으로 녹화 시작
  mediaRecorder.start(100);
}
```

**해설**: getUserMedia → MediaRecorder → 이벤트 핸들러 → start() 순서로 파이프라인을 구성합니다.

### Q9. 다음 요구사항을 만족하는 함수를 작성하세요.

- 함수명: `sendAudioChunkWithMetadata`
- 매개변수: `ws: WebSocket, blob: Blob, sequence: number`
- 반환값: `Promise<void>`
- 기능:
  1. WebSocket 연결 상태 확인
  2. 메타데이터 객체 생성 (type, sequence, timestamp, size, mimeType)
  3. 메타데이터를 JSON으로 전송
  4. Blob을 ArrayBuffer로 변환하여 전송
  5. 에러 처리

**정답**:

```typescript
async function sendAudioChunkWithMetadata(
  ws: WebSocket,
  blob: Blob,
  sequence: number
): Promise<void> {
  // 1. WebSocket 연결 상태 확인
  if (ws.readyState !== WebSocket.OPEN) {
    throw new Error("WebSocket이 연결되지 않았습니다.");
  }

  try {
    // 2. 메타데이터 객체 생성
    const metadata = {
      type: "audio",
      sequence: sequence,
      timestamp: Date.now(),
      size: blob.size,
      mimeType: blob.type,
    };

    // 3. 메타데이터를 JSON으로 전송
    ws.send(JSON.stringify(metadata));

    // 4. Blob을 ArrayBuffer로 변환하여 전송
    const arrayBuffer = await blob.arrayBuffer();
    ws.send(arrayBuffer);
  } catch (error) {
    console.error("전송 실패:", error);
    throw error;
  }
}
```

**해설**: 메타데이터와 오디오 데이터를 순서대로 전송하고, 에러를 적절히 처리합니다.

### Q11. 다음 요구사항을 만족하는 통합 에러 처리 함수를 작성하세요.

- 함수명: `handlePipelineError`
- 매개변수: `error: unknown, context: string`
- 기능:
  1. 에러 타입에 따라 적절한 메시지 생성
  2. DOMException인 경우 에러 이름별로 처리
  3. WebSocket 에러인 경우 처리
  4. 기타 에러 처리
  5. 사용자에게 알림 표시

**정답**:

```typescript
function handlePipelineError(error: unknown, context: string): void {
  console.error(`[${context}] 에러 발생:`, error);

  let userMessage = "알 수 없는 오류가 발생했습니다.";

  if (error instanceof DOMException) {
    switch (error.name) {
      case "NotAllowedError":
        userMessage = "마이크 사용 권한이 필요합니다.";
        break;
      case "NotFoundError":
        userMessage = "마이크를 찾을 수 없습니다.";
        break;
      case "NotReadableError":
        userMessage = "마이크가 다른 프로그램에서 사용 중입니다.";
        break;
      case "OverConstrainedError":
        userMessage = "요청한 설정을 지원하지 않습니다.";
        break;
      default:
        userMessage = `오류: ${error.message}`;
    }
  } else if (error instanceof Error) {
    if (error.message.includes("WebSocket")) {
      userMessage = "서버 연결에 실패했습니다. 잠시 후 다시 시도해주세요.";
    } else {
      userMessage = error.message;
    }
  }

  alert(userMessage);
}
```

**해설**: 다양한 에러 타입을 처리하고, 사용자에게 명확한 메시지를 표시합니다.

### Q12. 다음 요구사항을 만족하는 성능 최적화 함수를 작성하세요.

- 함수명: `optimizeAudioStreaming`
- 매개변수: `mediaRecorder: MediaRecorder, ws: WebSocket`
- 기능:
  1. timeslice를 적절한 값(100ms)으로 설정
  2. 불필요한 데이터 전송 방지 (크기가 0인 청크 제외)
  3. WebSocket 버퍼링 방지 (연결 상태 확인)
  4. 메모리 누수 방지 (사용하지 않는 스트림 정리)

**정답**:

```typescript
function optimizeAudioStreaming(
  mediaRecorder: MediaRecorder,
  ws: WebSocket
): void {
  // 1. timeslice를 100ms로 설정하여 실시간 전송
  mediaRecorder.start(100);

  // 2. 불필요한 데이터 전송 방지
  mediaRecorder.ondataavailable = async (event: BlobEvent) => {
    // 크기가 0인 청크는 무시
    if (!event.data || event.data.size === 0) {
      return;
    }

    // 3. WebSocket 연결 상태 확인
    if (ws.readyState !== WebSocket.OPEN) {
      console.warn("WebSocket이 연결되지 않아 전송을 건너뜁니다.");
      return;
    }

    try {
      const arrayBuffer = await event.data.arrayBuffer();
      ws.send(arrayBuffer);
    } catch (error) {
      console.error("전송 실패:", error);
    }
  };

  // 4. 정리 함수 제공 (외부에서 호출)
  return () => {
    if (mediaRecorder.state !== "inactive") {
      mediaRecorder.stop();
    }
    mediaRecorder.stream.getTracks().forEach(track => track.stop());
  };
}
```

**해설**: 실시간 스트리밍의 성능을 최적화하기 위한 여러 기법을 적용합니다.

### Q14. 실시간 오디오 스트리밍 시스템에서 전체 파이프라인의 각 단계와 데이터 흐름을 설명하세요.

**정답**:

**전체 파이프라인**:

1. **getUserMedia**: 마이크에서 오디오 스트림 획득
   - 입력: 없음
   - 출력: MediaStream
   - 데이터 형태: 실시간 오디오 스트림

2. **MediaRecorder**: 스트림을 녹화하여 데이터 수집
   - 입력: MediaStream
   - 출력: Blob (ondataavailable 이벤트)
   - 데이터 형태: 인코딩된 오디오 청크 (예: WebM)

3. **Blob → ArrayBuffer 변환**: WebSocket 전송을 위한 변환
   - 입력: Blob
   - 출력: ArrayBuffer
   - 데이터 형태: 바이너리 데이터

4. **WebSocket 전송**: 서버로 데이터 전송
   - 입력: ArrayBuffer (또는 메타데이터 JSON)
   - 출력: 서버 수신
   - 데이터 형태: 이진 데이터 또는 텍스트

5. **Django 서버 처리**: STT 처리 및 결과 반환
   - 입력: 오디오 데이터
   - 출력: 전사 결과 (JSON)
   - 데이터 형태: 텍스트

**데이터 흐름**:
```
마이크 → MediaStream → MediaRecorder → Blob → ArrayBuffer → WebSocket → Django 서버 → STT → 전사 결과
```

**해설**: 각 단계에서 데이터 형태가 변환되며, 실시간으로 처리되어야 합니다.
